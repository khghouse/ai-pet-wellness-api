- **반려견 삭제와 산책 상태 연동 설계**
  - **출처:** PR #32 코드 리뷰
  - **문제:** 산책 도메인과 진행 중인 산책 조회 계약이 아직 없어, 반려견 삭제 시 산책 존재 여부 확인과 `409 Conflict` 계약을 구현할 수 없다.
  - **제안:** 산책 도메인 설계 시 진행 중인 산책의 상태와 조회 계약을 정의하고, 반려견 삭제 제한과 산책 시작, 반려견 수정 요청 간 충돌 제어 방식 및 응답 정책을 함께 결정한다.
  - **영향:** 삭제된 반려견에 진행 중인 산책이 남는 상태와 삭제, 수정, 산책 시작의 경합을 방지할 수 있다.
  - **트레이드오프:** 산책 도메인 모델, 트랜잭션 경계, 동시성 제어 전략을 함께 설계해야 한다.

- **리워드 수령 자격 검증 설계 및 구현**
  - **출처:** 사용자
  - **문제:** 반려견 검증 없이 미션에 참여할 수 있어도, 경제적 가치가 있는 리워드는 실제 사용자와 반려견을 확인해야 한다.
  - **제안:** 미션 참여와 달성은 개방하되, 리워드 수령 시 사용자 본인인증과 반려견 검증 완료를 모두 요구한다.
  - **영향:** 리워드 부정 수급을 줄이고, 가족 구성원이 리워드를 수령할 때도 사용자와 반려견 검증을 분리해 판단할 수 있다.
  - **트레이드오프:** 본인인증 및 반려견 검증 외부 연동, 개인정보 처리와 검증 실패 정책이 필요하다.
