# REQ-011: 반려견 삭제

- **목표:** 인증된 소유자는 자신이 소유한 반려견을 삭제할 수 있다.
- **행위자:** JWT 인증된 `OWNER` 회원
- **범위:** 반려견 소프트 삭제 및 활성 멤버십 종료
- **관련 엔티티:** `Pet`, `PetMembership`
- **제외 범위:**
  - 반려견 삭제 취소 및 복구
  - 체중, 산책, 미션, 리워드 이력의 물리 삭제
  - 가족 구성원 초대 및 멤버십 역할 변경
  - 진행 중인 산책 자동 종료
  - 반려견 검증

## API

- `DELETE /api/v1/pets/{petId}`
- 성공 상태 코드: `200 OK`

## 입력값

### Path Variable

- `petId`: 반려견 식별자

## 응답값

- 없음

## 정책

- JWT 인증된 회원만 반려견을 삭제할 수 있다.
- 존재하고 삭제되지 않은 반려견만 삭제할 수 있다.
- 해당 반려견의 `ACTIVE` 상태 `OWNER` 멤버십을 가진 회원만 삭제할 수 있다.
- `FAMILY`, `LEFT` 멤버십 회원 또는 관계없는 회원은 삭제할 수 없다.
- 삭제 시 `Pet.deleted`를 `true`로 변경한다.
- 삭제 시 해당 반려견의 `ACTIVE` 멤버십만 `LEFT`로 변경한다.
- 이미 `LEFT`인 멤버십은 변경하지 않는다.
- 삭제된 반려견은 현재 반려견 목록과 반려견 관리 기능에서 제외한다.
- 체중, 산책, 미션, 리워드의 과거 이력은 삭제하지 않고 보존한다.
- 반려견 삭제와 활성 멤버십 종료는 하나의 트랜잭션으로 처리한다.
- 삭제 성공 응답에는 별도 데이터를 포함하지 않는다.
- 진행 중인 산책 존재 여부를 확인해 삭제를 제한하는 정책은 산책 도메인 구현 시 별도 요구사항으로 정의한다.
- 반려견 삭제와 반려견 정보 수정, 산책 시작이 동시에 요청되는 경우의 충돌 제어 방식과 응답 정책은 각 기능 구현 설계 단계에서 결정한다.

## 흐름

1. 인증된 회원이 반려견 삭제를 요청한다.
2. 시스템은 반려견이 존재하고 삭제되지 않았는지 확인한다.
3. 시스템은 요청 회원이 해당 반려견의 `ACTIVE` 상태 `OWNER` 멤버십을 보유하는지 확인한다.
4. 시스템은 반려견의 `deleted`를 `true`로 변경한다.
5. 시스템은 해당 반려견의 `ACTIVE` 멤버십을 모두 `LEFT`로 변경한다.
6. 시스템은 본문 없는 성공 응답을 반환한다.

## 완료 기준

- [ ] 인증되지 않은 사용자는 반려견을 삭제할 수 없다.
- [ ] 존재하지 않거나 이미 삭제된 반려견은 삭제할 수 없다.
- [ ] `ACTIVE` 상태의 `OWNER` 회원은 반려견을 삭제할 수 있다.
- [ ] `FAMILY`, `LEFT` 멤버십 회원 또는 관계없는 회원은 삭제할 수 없다.
- [ ] 삭제 성공 시 반려견의 `deleted`는 `true`가 된다.
- [ ] 삭제 성공 시 해당 반려견의 `ACTIVE` 멤버십만 `LEFT`가 된다.
- [ ] 이미 `LEFT`인 멤버십은 유지된다.
- [ ] 반려견 삭제와 활성 멤버십 종료는 함께 성공하거나 함께 실패한다.
- [ ] 삭제된 반려견은 현재 반려견 목록에서 제외된다.
- [ ] 체중, 산책, 미션, 리워드의 과거 이력은 보존된다.
- [ ] 삭제 성공 응답에는 별도 데이터가 포함되지 않고 HTTP 상태 코드는 `200 OK`다.

## 예외

- 반려견 없음 또는 이미 삭제된 반려견
- `OWNER` 멤버십 없음 또는 종료된 멤버십

## 테스트 기준

- `OWNER` 회원 반려견 삭제 성공
- 미인증 사용자 삭제 실패
- `FAMILY`, `LEFT` 멤버십 회원 및 관계없는 회원 삭제 실패
- 존재하지 않거나 이미 삭제된 반려견 삭제 실패
- 삭제 성공 시 반려견의 `deleted` 변경 확인
- 삭제 성공 시 활성 멤버십만 `LEFT`로 변경되고 기존 `LEFT` 멤버십은 유지되는지 확인
- 삭제 후 현재 반려견 목록에서 제외되는지 확인
- 삭제 후 체중, 산책, 미션, 리워드 이력이 보존되는지 확인
- 트랜잭션 실패 시 반려견과 활성 멤버십 상태가 함께 유지되는지 확인
- 본문 없는 성공 응답과 `200 OK` 확인
